# Apps in Toss MVP Plan

마인드루트의 앱인토스 버전은 웹 전체를 옮기는 앱이 아니라, `고민 선택 -> 원인 후보 -> 근거 있는 방법 -> 행동 기록`만 압축한 미니앱으로 시작한다.

## 1차 MVP

- 진입 화면: 오늘 다룰 고민 하나 선택
- 원인 후보: 사용자가 자기 상태에 가까운 원인을 하나 고름
- 근거 방법: 출처가 확인된 철학자, 연구자, 저작의 관점을 행동 제안으로 변환
- 트래커: 행동 체크, 짧은 메모, 진행률 저장

현재 웹 프리뷰 경로는 `/toss`다.

## 앱인토스 적합성

앱인토스는 토스 앱 안에서 실행되는 미니앱 플랫폼이므로, 사용자가 길게 탐색하기보다 한 번 들어와 바로 행동을 끝내는 구조가 맞다.

따라서 첫 버전은 아래 기능을 제외한다.

- 긴 글 탐색
- 논쟁/찬반 콘텐츠
- 외부 링크 중심의 출처 탐색
- 복잡한 회원가입
- 의료 진단, 상담, 치료처럼 보이는 표현

포지션은 `정신건강 치료`가 아니라 `자기개발 루틴 / 생각 정리 / 행동 기록`이다.

## 공식 문서 기준 메모

- 기존 웹 프로젝트는 `@apps-in-toss/web-framework` 설치와 `npx ait init`으로 앱인토스 SDK 연동을 시작할 수 있다.
  - https://developers-apps-in-toss.toss.im/tutorials/webview.html
- 비게임 미니앱은 SSR을 사용하지 않고 CSR 또는 SSG 방식으로 구현해야 한다.
  - https://developers-apps-in-toss.toss.im/checklist/app-nongame.html
- 토스 로그인을 쓰는 경우 자사 로그인이나 기타 로그인 방식은 제공하지 않는 방향으로 봐야 한다.
  - https://developers-apps-in-toss.toss.im/checklist/app-nongame.html
- 앱 번들은 압축 해제 기준 100MB 이하 정책을 고려해야 한다.
  - https://developers-apps-in-toss.toss.im/development/test/toss.html
- 의료, 금융, 투자, 사행성 등 제한 카테고리와 자사 앱 설치/외부 링크 유도 제한을 피해야 한다.
  - https://developers-apps-in-toss.toss.im/intro/guide.html

## 구현 순서

1. 웹 내부 `/toss` 프리뷰로 핵심 루프 검증
2. 실제 앱인토스 프로젝트를 별도 디렉터리로 생성
3. 현재 프리뷰의 데이터 구조를 미니앱 프로젝트로 이식
4. 토스 사용자 식별키와 서버 저장 구조 설계
5. 알림/리텐션은 검수 가능성이 확인된 뒤 추가
6. 광고나 결제는 행동 기록 리텐션이 먼저 확인된 뒤 검토

## 제품 기준

좋은 첫 버전은 많은 콘텐츠를 보여주는 앱이 아니라, 사용자가 30초 안에 아래를 끝내는 앱이다.

1. 지금 고민을 고른다.
2. 내 원인에 가까운 것을 고른다.
3. 믿을 만한 방법 하나를 고른다.
4. 오늘 할 행동을 체크한다.
5. 짧게 기록하고 다음 방문 이유를 남긴다.

## 다음 확장 후보

- 사용자가 고른 원인에 따라 루틴이 자동으로 바뀌는 구조
- 오늘 기록이 쌓이면 `내 반복 패턴`을 보여주는 화면
- 토스 로그인 기반 저장
- 토스 푸시/알림 기반 3일 루틴 리마인드
- 공유 리워드보다 먼저 친구에게 고민 카드를 보내는 가벼운 공유
